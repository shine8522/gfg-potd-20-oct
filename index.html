Lexicographically Largest Array with Even-Sum Adjacent Swaps

Swap adjacent arr[i], arr[i+1] only if their sum is even. Return the lexicographically largest array possible.

A. What is the goal?

A = [8, 2, 9], B = [7, 100, 100]. Compare left to right and stop at the first difference.

Press the button.
Question: what do we want at the earliest position?

The biggest value we can legally get there. Then the biggest possible at position 2, and so on. Note: legally. That word matters.

B. Challenge the first thought

"Bring the largest element to the front." Try it on [2, 9, 4, 7]: click the gap between two cells to attempt a swap.

Can 9 reach index 0? Try it.

9+2 and 9+4 are odd, so 9 is stuck. Value alone does not decide movement; the allowed operations do. No jumping, only adjacent swaps.

C. The parity rule

even+even = even, odd+odd = even, even+odd = odd. So two neighbours swap exactly when their parities match.

D. The boundary invariant

On [3, 1, 5, 2, 4] the red bar sits between 5 and 2 (sum 7, odd). Click gaps to swap.

  1. Same parity, adjacent: swap directly.
  2. Same parity, separated by same-parity elements: become adjacent after legal swaps.
  3. Opposite parity: never swap, so never cross. Every swap preserves the ODD/EVEN pattern, so maximal same-parity groups keep fixed positions.

E. Best arrangement inside a group

Group [3, 1, 5] arrangements: [5,3,1] beats [1,5,3] and [3,1,5]. The earliest slot gets the group's largest, the next slot the largest remaining, and so on, which is descending order.

[3,1,5 | 2,4] → [5,3,1 | 4,2] = [5, 3, 1, 4, 2]

Groups cannot trade elements, so each group must be maximized in its own positions. The first differing index in any other arrangement holds a smaller value, so by the definition of lexicographic order it loses.

F. Pointer algorithm, line by line

vector<int> lexicographicallyLargest(vector<int> &arr) {
        // code here
        int n=arr.size();
        int i=0;
       
        while(i<n){
             int j=i+1;
           while(j<n && arr[j-1]%2==arr[j]%2){
               j++;
           }
          sort(arr.begin() + i, arr.begin() + j, greater<int>());
           i=j;
        
        }
        return arr;
        
    }
Why each line exists

n: the length is used in every bounds check. i = 0: first unprocessed index and start of the current group. while (i < n): every group must be handled and we must not read past the end.

j = i + 1: a group has at least the element at i, so the scan starts one step right.

Inner while: j < n is first so C++ short-circuiting never evaluates arr[j] out of bounds. We compare neighbours arr[j-1] and arr[j]: a run where every adjacent pair matches is exactly a maximal same-parity group (parity matching is transitive, and comparing only to arr[i] would give the same answer but hides the "adjacent swap" meaning). When the loop stops, j is the first index not in the group, an exclusive end, so the group is indices i..j-1, i.e. [i, j).

sort: arr.begin()+i points at index i, arr.begin()+j points one past the group, so the range is half-open. greater<int>() orders larger first. Sorting only this range cannot move anything across a barrier.

i = j: the next group starts exactly where this one ended, so no index is skipped or repeated. return arr: every group is now maximal in place.

Negatives: the code above is exact for non-negative inputs. In C++ -3 % 2 == -1 but 3 % 2 == 1, both odd, so if negatives are allowed, change the condition to ((arr[j-1]%2)+2)%2 == ((arr[j]%2)+2)%2. The dry run below uses this normalized parity, so it matches your code on non-negative input and stays correct on negatives.

I. Proof you can say aloud


Feasibility. The only move is an adjacent swap, forbidden for opposite parity, so opposite-parity elements never cross and group positions are fixed.


Group optimality. Inside a same-parity group every adjacent swap is legal, so (like bubble sort) every permutation is reachable. Descending order is the lexicographically largest permutation.


Global optimality. Groups cannot exchange elements, so the array is lexicographically largest when each group is largest in its own slots.



J. Complexity


Scanning is O(n). Sorting costs O(k₁log k₁ + … + kₘlog kₘ) for group sizes kᵢ summing to n, so worst case O(n log n) (one big group). All singletons: O(n). Auxiliary space is typically O(log n) for std::sort's recursion, not counting the input/output array.

L. Interview practice


1. Why can't an even element move left past an odd one, even from several positions away?
Hint: what must happen physically to cross? Answer: Crossing needs an adjacent swap of that even and that odd at some moment, and their sum is odd, so it is forbidden.


2. Why is descending order optimal inside a group?
Hint: look at the first slot. Answer: Lexicographic order is decided at the first difference, so the first slot must hold the group's maximum, then the second slot the max of the rest, which is descending.


3. Why is j an exclusive endpoint after the inner loop?
Hint: why did the loop stop? Answer: It stops when j == n or arr[j] breaks the parity chain, so arr[j] is not in the group; the group is i..j-1, i.e. [i, j).


Recap: Goal → swap restriction → parity invariant → fixed groups → descending order → two pointers → correctness proof.
